Setup and the projection

A fresh Angular app with the two libraries the whole project leans on, the paper-and-ink look from data-viz, and a full-screen map that has a projection but no geography yet: a graticule, fitted to the story's lands. Getting the projection right first means every later layer (rivers, treaty lines, traced Roman forts) lands on the same drawing.

1. The command

npx @angular/cli@21 new romanian-borders --directory . --style=scss --routing --ssr=false --zoneless --skip-git --skip-tests --ai-config=none
npm install d3-geo gsap
npm install -D @types/d3-geo @types/geojson prettier

3. The projection: Lambert conformal conic

geoConicConformal()
  .parallels([44, 48])  // true scale along these two
  .rotate([-25, 0])     // 25° E becomes the central meridian: it stands upright
  .fitExtent([[16, 16], [w - 16, h - 16]], core)  // the story's lands, always fully in view
  • Why a conic. A cone touching the globe along mid-latitudes is the classic choice for a region wider than it is tall, at 40°–50° N. Meridians become straight lines that lean together towards the north, parallels become arcs. That's the shape of every European atlas plate the trace tool will georeference later.
  • Why these parallels. Romania runs from 43.6° N (Zimnicea, on the Danube) to 48.3° N (Maramureș, Bukovina). 44° and 48° sit just inside each end (the usual rule of thumb is a sixth of the span in, 44.4° and 47.5°, rounded here to whole degrees), so the scale error is shared across the country instead of piling up at one edge.
  • Why conformal. A conformal map keeps angles, so small shapes keep theirs: the Carpathian arc bends the way it does on the ground, and river courses that later borders snap to aren't sheared. Over a region this small the area error is tiny anyway (table below), so comparing the size of Bessarabia and Transylvania stays fair.
  • The alternative. geoConicEqualArea with the same parameters would look the same at this scale, trading the tiny area error for a tiny shape error. Romania's national grid, Stereo 70, is an oblique stereographic centred on the same point, 25° E 46° N, and would also do. Mercator would not: see the last column.

4. Full screen: fit the core, show the area

  • data-viz's flat map draws into a fixed 960 × 500 viewBox and lets the SVG scale. That letterboxes a full-screen map. Here a ResizeObserver on the host writes its size into a signal, and the projection is a computed() that refits to it. Resize the window and the map refits.
  • Two boxes, both between two meridians and two parallels (geoGraticule().extent(…).outline(), a fan, not a rectangle, in this projection). The core, 20°–30.5° E and 43°–48.5° N, covers every state the story will show, from the Tisza plain to the Dniester's mouth, the Balkan range to Galicia: fitExtent fits it, so it is always fully in view with 16 px to spare. The area, 16.5°–34° E and 41.2°–50.2° N, is the core and about a fifth more on every side: the data covers it, so the map runs full bleed to the window's edges on every landscape screen from 4:3 to 16:9 (an ultrawide or portrait window shows paper and graticule at its far edges).
  • Both, and the projection's parameters, live in one file, src/app/data/region.json, read by the app and by the build scripts, so the data, the satellite picture and the map always agree.
  • No neatline and no degree labels: a picture book's map runs to the edge. (The first version drew the core as an ink frame with degree labels and a red cross at the centre; they went when the map went full bleed.)
  • The graticule runs well beyond the area (5°–45° E, 33°–60° N). d3 resamples the lines adaptively, so the parallels come out as smooth arcs, not polylines.
  • The projection is set up once per size, the path strings come from geoPath in computed(), and the template only binds [attr.d]. No d3.select: D3 does the math, Angular does the DOM, as in data-viz.
